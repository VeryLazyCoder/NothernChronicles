# Проверки проекта

## Что проверено при подготовке

На 18 октября 2026 года:

- `npm test`: 18 успешных тестов Node.js, включая 100 полных симулированных партий.
- `npm run check`: синтаксис app.js, game.js и transport.js проверен.
- HTTP-раздача: index.html и ES-модули возвращают 200.
- Headless Chrome: старт с 10 картами и 6 рядами; 14 записей коллекции; фильтр ближнего боя; просмотр карты; шесть разделов правил; форма WebSocket-подключения.
- Реальные клики в Chrome: выбор карты, допустимый ряд, ответ локального бота, отмена/подтверждение паса, следующий раунд, окончание матча и новая партия.
- Эмуляция viewport 390 px: документ имеет scrollWidth=390, без горизонтального переполнения страницы; карта выбирается и разыгрывается. Рука прокручивается отдельно.
- Просмотр снимков интерфейса на широком и узком экранах; необработанных JavaScript-исключений в браузерном прогоне не обнаружено.

WebSocketTransport протестирован с подставным сокетом и fetch: cookie-сессия до WebSocket, подтверждение requestId, pending, принятие снимков, игнорирование старой revision, ERROR, RESUME без повтора хода, блокировка несовместимого протокола и незащищённого ws для HTTPS-страницы.

**Реальный Java backend отсутствует**, поэтому совместимость с вашим будущим сервером, два настоящих сетевых игрока, реальные cookies/CORS, технические поражения и восстановление сети не проверены. Unit-тест с подставным сокетом не заменяет интеграционный тест Java+браузеры.

## Команды

Из корня проекта:

```powershell
npm test
npm run check
npm start
```

Никаких npm-зависимостей и `npm install` не требуется. Обычного Node.js 20+ достаточно. В ограниченной среде подготовки Windows для доступа Node к workspace использовались `--preserve-symlinks --preserve-symlinks-main`; пользователю обычной локальной среды эти флаги не нужны.

## Ручная проверка frontend

1. Откройте localhost:5173: 2 жизни на сторону, по 10 карт, нулевые очки, ваш ход.
2. Выберите обычного бойца: подсвечивается только его свой ряд. Щелчок переносит карту из руки, меняет силу, затем отвечает бот.
3. Выберите героя: сила 10. При погоде на его row сила героя сохраняется.
4. Разыграйте погоду: действует на обе стороны. Повторную такую же погоду сервер/демо отклоняет без расхода карты.
5. Разыграйте рог, выбрав свой ряд. После погоды сила обычного бойца становится 2, герой не удваивается.
6. Разыграйте ясное небо. Если погоды нет, получите понятную ошибку без расхода хода.
7. Нажмите «Пас», сначала отмените, затем подтвердите. После подтверждения ходить больше нельзя до нового раунда.
8. После двух пасов виден итог раунда. Нажмите «Следующий раунд»: поле очищается, оставшаяся рука не пополняется.
9. Доиграйте до двух потерянных жизней; начните новую партию.
10. Откройте коллекцию, отфильтруйте по ряду, прочитайте описание специальной карты и правила.
11. Повторите на ширине 390 px и с клавиатуры: Tab, Enter/Space, Escape в диалогах. Для погоды кнопка доступна над рукой даже без правой панели.

Начальная колода случайная, поэтому для ручной проверки всех типов может потребоваться несколько партий. Для детерминированных проверок используйте tests/game.test.js; не изменяйте продуктивную колоду ради прохождения случайного ручного сценария.

## После реализации Java backend

1. Обычный профиль браузера + приватное окно. Разные имена, одна комната. Вкладки одного профиля разделяют guest-cookie.
2. Честный обмен ходами; своя hand видна только владельцу в WS frames. Чужого deck нет ни у кого.
3. Сервер отвергает чужой экземпляр, неверный ряд, чужой ход, плохой enum, слишком большое сообщение, неучастника матча.
4. Две команды одной revision не дают двух изменений; тот же requestId не тратит карту второй раз.
5. STALE_REVISION даёт ERROR и актуальный SNAPSHOT. После этого UI показывает новое поле, повторный ход требует нового решения игрока.
6. Потеря связи после commit до ответа → RESUME возвращает принятый ход, без двойной карты.
7. Краткий разрыв соединения восстанавливается; grace period и технический исход проверяются отдельными серверными тестами с управляемыми часами.
8. Две готовности завершают ROUND_OVER; ничья снимает жизни с обеих сторон; обе нулевые жизни дают ничью матча.
9. При перезапуске сервера in-memory MVP честно сообщает MATCH_NOT_FOUND, а не создаёт незаметно новую игру.
